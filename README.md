# DEAD LOOP

> Every death leaves something behind.

2D 精準平台跳躍 × 時間循環解謎。每一次死亡都會把你的輸入錄下來，下一輪由「過去的你」原封不動地重演；你要讓不同時間線的自己互相合作，完成一個人做不到的房間。

**v1.3 — 40 間房＋3 間 Special Room、7 個世界**：新增模仿者、巨人、落錘、相位地面（PARADOX），並修正捷徑。

**v1.2 — 30 間房、6 個世界，硬核跑酷為主軸、解謎為骨架**：蹬牆、彈簧、衝刺晶體、崩塌地板、輸送帶、雷射、計時開關、反向門與「回聲房」（過去的自己可以踩）。每個新機制只用一間房引入，之後就直接放進困難的組合裡；每一間都有腳本驗證的解法。

## 快速開始

```bash
npm install
npm run dev        # http://localhost:5173
npm run check      # 型別檢查 + lint + 測試（每個 Phase 結束都應全綠）
npm run build      # 輸出到 dist/
```

需要 Node.js 20 以上。

## 部署到 Render

本專案是純前端 SPA，不需要後端。

1. 推上 GitHub。
2. Render → **New → Blueprint**，選這個 repo，Render 會讀取 `render.yaml` 自動建立 Static Site。
   （或手動建立 **Static Site**：Build Command `npm ci && npm run build`，Publish Directory `dist`）

另外 `npm run build:single` 會產出單一 HTML 檔（`dist-single/index.html`），方便直接傳給別人試玩。

## 架構

```
src/
├── game/                 ← 遊戲核心，不依賴 React
│   ├── constants.ts      所有物理數值（每 tick）
│   ├── character.ts      唯一的角色控制器：玩家和 Replay 共用同一份程式碼
│   ├── physics.ts        逐像素移動與碰撞（含 one-way 平台）
│   ├── room.ts           房間模擬：Loop 生命週期、Replay、屍體、Walker、壓力板、門
│   ├── level.ts          關卡 JSON 驗證
│   ├── input.ts          鍵盤 → 每 tick 一個 bitmask byte
│   ├── render.ts         Canvas 繪製（只讀取狀態，絕不寫回模擬）
│   ├── audio.ts          WebAudio 合成音效與環境音（無外部素材）
│   ├── save.ts           localStorage（deadloop_save），損壞會自動修復
│   └── state.ts          GameState 單一判斷點
├── levels/levelNN.json   資料驅動的關卡
└── ui/                   React：選單、HUD、暫停、設定、關卡選擇
tests/                    Vitest：決定性、關卡可解、生命週期
scripts/build_levels.py   用程式「畫」關卡並輸出 JSON 的開發工具
```

### Replay 系統的幾個保證

- **Replay 是輸入錄製，不是影片**：每個 simulation tick 存一個 byte（左/右/跳/衝刺 bitmask），存成 `Uint8Array`。
- **固定步進 60 tick/s**：畫面 FPS 高低只影響繪製；模擬只看 tick 數，所以 Replay 不會因 FPS 漂移。
- **Replay 走和玩家完全相同的 `stepCharacter()`**：輸入 → 物理 → 碰撞，從不直接套用位置。環境改變時（例如門開了、敵人被別人引走），Replay 的結果會跟著改變——這是設計，不是 bug。
- **沒有 `Math.random()`、沒有真實時間**：模擬中唯一的「隨機」只在繪製特效裡，且用獨立的 seeded RNG。
- **同一 tick 內，所有角色都讀取上一 tick 結束時的世界**，所以角色處理順序不影響結果。
- **畫面外照常模擬**，只有繪製會略過。
- `replayCollisionEnabled`（目前為 `false`）已預留給未來的 Replay 互撞。
- 安全上限 50 個 Replay／房間，超過會丟掉最舊的。

`npm test` 裡的決定性測試會：用同一組輸入跑兩個房間並逐 tick 比對快照；確認每一關第一個 Replay 在世界未改變時，會在完全相同的 frame 和座標死亡；以及用不規則的「幀節奏」跑同一串 tick，結果必須相同。

### 關卡 JSON 格式

```jsonc
{
  "id": "level02", "name": "Again", "world": "LEARNING TO DIE",
  "width": 32, "height": 16,
  "spawn": { "x": 2, "y": 12 },       // tile 座標；角色站在這一格上
  "exit":  { "x": 28, "y": 12 },      // 出口底部所在的 tile（1×2 格）
  "loopDuration": 30,                 // 選填：每輪秒數上限
  "tiles": [ "################", "#..............#", ... ],
  "objects": [
    { "id": "p1", "type": "plate", "x": 5, "y": 12, "width": 1, "height": 1, "properties": { "target": "d1" } },
    { "id": "d1", "type": "door",  "x": 25, "y": 10, "width": 1, "height": 3, "properties": { "require": "all" } },
    { "id": "w1", "type": "walker","x": 20, "y": 12, "properties": { "patrol": [19, 22], "sight": 5, "dir": 1 } },
    { "id": "h1", "type": "hint",  "x": 3, "y": 8, "properties": { "text": "…" } },
    { "id": "s1", "type": "plate", "x": 3, "y": 13, "properties": { "target": "d1", "latch": true } },
    { "id": "t1", "type": "plate", "x": 7, "y": 12, "properties": { "target": "d3", "hold": 1.5 } },
    { "id": "m1", "type": "platform", "x": 15, "y": 14, "width": 3,
      "properties": { "to": { "x": 15, "y": 6 }, "speed": 0.8, "pause": 50, "delay": 0 } },
    { "id": "e1", "type": "platform", "x": 12, "y": 14, "width": 3,
      "properties": { "to": { "x": 12, "y": 6 }, "mode": "plate" } },
    { "id": "z1", "type": "laser", "x": 18, "y": 1, "properties": { "dir": "down" } },
    { "id": "z2", "type": "laser", "x": 9, "y": 1, "properties": { "dir": "down", "pulse": { "on": 70, "off": 80, "phase": 0 } } },
    { "id": "z3", "type": "laser", "x": 1, "y": 12, "properties": { "dir": "right", "offset": 13 } }
  ]
}
```

Tile 字元：`#` 實心、`^` 地刺、`v` 天花板刺、`>` / `<` 牆上側刺（朝右／朝左）、`=` 單向平台、`g` 可蹬牆的牆、`x` 崩塌方塊、`.` 空。

關卡層級選項：`loopDuration`（秒，每輪倒數）、`solidGhosts: true`（回聲房：活著的過去自己可以站，較新的自己可以站在較舊的自己身上）。

物件補充：
- **plate**：`target` 可以是門、平台或雷射（字串或陣列）。`latch: true` = 開關（整輪保持）；`hold: 秒數` = 計時開關（離開後再保持幾秒）。
- **door**：`require: "all"` 需要所有連到它的板；`invert: true` = 反向門（平常開、有人踩才關）。關著的門會擋雷射。
- **platform**：單向平台（可從下方穿過），會帶著站在上面的角色、屍體、敵人一起移動。預設來回移動（`speed` 像素／tick、端點停 `pause` tick、開場延遲 `delay`）；`mode: "plate"` = 被踩住時往 `to` 移動，放開就回去。
- **laser**：從發射器中心沿 `dir` 射出，停在第一個實心格、關著的門、屍體或平台。碰到的角色會死；Walker 會被燒掉。有連到壓板時為「壓住就關」（`invert: true` 反過來）；有 `pulse` 時依 tick 週期開關（`on`／`off` 為 tick 數），熄滅的最後 0.6 秒會閃爍預告。`offset` 是光束在格子內的位置（像素，預設 8；13 = 貼地，屍體擋得住）。
- **spring**：嵌在地面的彈簧（`width` 可多格），把站上去的活物往上彈約 7 格；有屍體躺在上面就會卡住，變成普通地板。
- **orb**：衝刺晶體，碰到會補回空中衝刺，`respawn` 秒後長回來（預設 2.5 秒）。過去的自己也會吃掉它。
- **conveyor**：鋪在實心地面上的輸送帶，`speed` 像素／tick（負數向左）；會帶動角色、屍體與 Walker。可被壓板反轉。
- **walker**：另有 `sightY`（格）控制垂直視野；Walker 也會踩碎崩塌地板。
- `loopDuration`（秒）：每輪倒數。時間到時「你」死在原地；Replay 不受影響（反正那一輪也結束了）。

新增關卡：把 `levelNN.json` 放進 `src/levels/`（會依檔名自動載入），並在 `tests/solutions.ts` 補一份解法。`scripts/build_levels.py` 是我畫關卡用的腳本，`npx tsx scripts/try.ts levelNN 10` 可以跑解法並每 10 tick 印出狀態。

## 與企劃書的差異（依第 90 節：明確指出衝突＋最小修改）

1. **Walker 會追人（§24 vs §25/26）**：§24 說 Walker 只左右巡邏、撞牆轉向，但 §25/26 要求「Replay 吸引敵人」「敵人壓按鈕」。純巡邏的敵人無法被吸引，所以加了最小規則：視野內（水平 `sight` 格、垂直約 2.5 格）有活著的角色時朝最近者移動，否則巡邏；任何時候都不會走下懸崖。只追活人，屍體不吸引。
2. **屍體會垂直落下（§21）**：沒有 ragdoll，但會受重力直落，停在地面、其他屍體上，或**停在尖刺尖端上**。這讓「死在刺上 → 變成踏腳石」「空中被殺 → 屍體掉到壓力板上」都能被看懂。屍體是單向平台：可以站上去，但不會卡住人。
3. **Z 撤銷上一輪**：企劃書沒有。只刪最後一個 Replay，不算死亡。在多輪解謎時比 R 全部重來友善很多；若不想要，刪掉 `GameView.tsx` 裡 `KeyZ` 那一行即可。
4. **門不會夾死人**：該關門時若有角色、屍體或敵人在門框裡，門會等到淨空才關。比「夾死」更可預期，也避免 Replay 因邊界時機而飄移。
5. **跳下地圖不留屍體**：掉出邊界的角色直接消失。
6. **新增兩種開關（v1.1）**：企劃書只有壓力板。為了讓 World 2 與 World 5 有新東西可學，加了「開關」（碰一下整輪保持）與「計時開關」（離開後保持幾秒）。兩者都只是壓力板的屬性，沒有新系統。
7. **雷射細節（v1.1）**：屍體會擋雷射、雷射會燒掉 Walker（不留屍體）。這兩條規則撐起 World 4 的「盾」與「誘敵燒毀」。脈衝雷射在開火前 0.6 秒會閃爍，符合 §56「沒有預兆的攻擊」禁止。
8. **倒數只殺「你」（v1.1）**：時間到時玩家死在原地（會留屍體）；Replay 不會被倒數殺死。這讓「站在板上等時間到」成為合法的長時間固守方式。
